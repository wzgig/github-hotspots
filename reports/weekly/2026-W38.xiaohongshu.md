01｜ECC
给 AI 编程助手配上规划、测试、审查和记忆流程，不必每次从提示词重新搭建。

它能做什么：

- 把功能需求整理为可确认的实施计划
- 用先写失败测试的流程推进代码修改
- 在独立上下文中复查代码变更
- 将会话经验提炼为可复用技能
- 扫描智能体配置中的权限与注入风险

核心亮点：让编程助手按工程流程交付。把规划、先写测试、实现、独立审查和最终验证串成流程，再将会话经验存为记忆与技能。规则持续生效，技能按需加载，事件触发脚本负责流程检查。

适合谁：用 AI 编程助手开发功能、修复缺陷，希望把测试、审查和会话交接纳入固定流程的研发人员。
使用前准备：通用安装包需 Node.js 18 或更新版本；Claude 插件安装还需 Git 和 Claude Code 2.1 或更新版本。

使用提醒：各编程助手的功能不完全一致；同一助手勿叠加安装。启用脚本需明确授权，记忆内容仍须核验；私有仓库托管分析属于付费 Pro。Windows 原生记忆写入存在已知缺陷。

许可证：MIT

02｜gods-eye-view
把公开航班、卫星和摄像头放进浏览器地球，让你从全球概览一路查看到单个目标。

它能做什么：

- 追踪航班并切换随行驾驶舱视角
- 查看卫星位置与轨道环
- 把公共摄像头画面投射进三维场景
- 用语音绘制区域边界和地图标注
- 沿选定的道路路线生成镜头飞行

核心亮点：在同一地球视图切换公开信号。将航班、船舶、卫星和公共摄像头等来源放进同一地球视图。点选目标可跟踪轨迹、查看数据，再切换随行镜头或附近摄像头，从全球概览深入局部。

适合谁：想在地图中探索公开航班、卫星与城市数据，或制作地理可视化演示、扩展数据图层的人。
使用前准备：可用 Pinokio 8.2 或更新版本启动，无需密钥；写实三维需地图服务凭据，语音需 OpenAI 密钥。

使用提醒：数据可能延迟或错误，车辆位置为模拟、摄像头姿态为估计；不可用于导航或应急决策。语音按量付费，地图受配额约束；共享服务会让可访问者调用所配接口。不提供个人追踪。

许可证：MIT License（Bundled and live datasets carry their own terms）

03｜deepseek-harness
为开发者提供以插件组织能力的智能体运行框架，并通过网页界面启动使用。

它能做什么：

- 通过 npm 启动智能体网页界面
- 从源码构建并运行网页服务
- 关闭启动时自动打开浏览器的行为

核心亮点：以插件组织智能体运行框架。以 Cordis 为基础，将插件作为智能体运行框架的组织方式。可通过 npm 启动网页界面，也可构建源码后运行；README 尚未展开具体任务工具清单。

适合谁：希望试用插件化智能体运行框架、开发配套插件，并能接受兼容性变更的开发者。
使用前准备：需安装 Node.js；从源码运行还需用 pnpm 安装依赖并先完成构建。

使用提醒：目前处于开发者预览阶段，会发生破坏兼容性的变更；运行前需阅读安全说明。源码启动使用已构建产物，不会自动重新构建。

许可证：MIT

04｜open-code-review
在提交或合并前，把代码差异交给审查工具，返回具体到代码行的结构化意见。

它能做什么：

- 审查暂存、未暂存和未跟踪的代码变更
- 检查指定提交或分支区间的修改
- 扫描没有有效差异的完整文件
- 恢复中断的提交审查或全文件扫描
- 导出结构化 JSON 审查结果

核心亮点：程序管流程，模型查上下文。程序先筛选文件、组合相关变更并匹配规则，再让模型读取上下文、搜索代码。独立模块负责评论定位与复查，把审查发现整理成具体到代码行的意见。

适合谁：需要在提交、分支合并或接手陌生代码库时，获得具体到代码行的审查意见的研发团队。
使用前准备：需 Git >= 2.41；审查前需配置模型服务与模型，委托现有编程助手审查的模式除外。

使用提醒：README 报告的基准测试中，召回率低于通用智能体，取舍偏向减少误报而非找全缺陷；默认模式会将变更文件发送给所配置的模型。

许可证：Apache-2.0

为什么本期上榜：GitHub Trending 显示过去 7 天 +15,028 Star
GitHub 搜索：alibaba/open-code-review

05｜WeKnora
把团队散落的文档变成带引用的问答知识库，再自动整理为可维护的 Wiki。

它能做什么：

- 同步飞书、GitLab、Notion 等来源文档
- 检索知识库并生成带引用的回答
- 将原始文档整理成互相链接的 Wiki
- 编辑检索片段并回滚历史版本
- 把知识问答接入企业微信或飞书

核心亮点：文档既能问答，也能整理成 Wiki。文档导入后既能先检索资料再生成回答，也能由智能体整理成互相链接的 Markdown 页面与知识图谱。页面和检索片段均可人工修改、比较版本并回滚。

适合谁：需要把团队文档集中检索、维护内部知识库，并在企业聊天渠道提供资料问答的知识管理与研发团队。
使用前准备：部署需 Docker、Docker Compose 和 Git；使用本地 Ollama 模型前需先启动其服务。

使用提醒：自动提取的长期记忆需用户确认；Docker 技能沙箱需主动启用。README 建议部署在内网或私有网络，避免直接暴露公网，并配置访问控制。

许可证：MIT License（You are free to use, modify, and distribute the code with proper attribution.）

06｜i-have-adhd
嫌编程助手铺垫太长？这个技能让它先给操作，再按编号讲步骤，不把答案埋在长文里。

它能做什么：

- 把下一步操作放在回答开头
- 为多步骤任务添加编号
- 在每轮回复中重述当前状态
- 压缩跑题内容和客套话
- 用一个具体下一步结束回答

核心亮点：把下一步操作放在回答最前面。通过一组回复规则改变编程助手的表达顺序：先给行动，再编号拆解步骤，交代当前状态，最后只留一个下一步。重点是让答案容易找到，而非替用户安排日程。

适合谁：读编程助手长回复时容易漏掉重点，希望先看到操作、再按步骤执行的人，无需 ADHD 诊断。
使用前准备：需将技能或插件安装到编程助手中使用。

使用提醒：规则针对模型如何回复，不是指导人如何安排一天；替换成自定义副本前需移除原插件，随后重启助手并重新调用。

许可证：MIT

07｜skills
让编程助手先问清需求，再拆任务、写测试和审查；你可以按需组合技能，而非交出整个流程。

它能做什么：

- 通过连续提问澄清需求与设计分歧
- 将讨论整理为可发布的需求规格
- 把计划拆成标有阻塞关系的任务单
- 按先失败后通过的测试循环实现功能
- 分别核对代码规范与需求实现情况

核心亮点：把工程习惯拆成可组合技能。用小型、可组合的技能替代包办流程：先通过提问对齐需求，把项目术语和决策写进文档，再拆任务、写测试与审查。可选择托管插件，或保留可编辑的技能副本。

适合谁：希望保留开发流程控制权，用编程助手澄清需求、拆任务、写测试和审查实现的软件工程师。
使用前准备：每个仓库使用工程技能前需运行初始化技能，选择任务追踪方式、分诊标签及文档保存位置。

使用提醒：插件是自动更新的只读包，文件副本可编辑但需自行更新；两种方式勿同时安装。架构技能提供改进候选，不会自动理顺老代码库。

许可证：MIT
