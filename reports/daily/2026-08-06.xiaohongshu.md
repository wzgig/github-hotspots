01｜skills
把软件工程方法拆成可组合技能，帮助编程 Agent 澄清需求、测试代码和改进设计

它能做什么：

- 追问需求并在动手前对齐变更目标
- 建立共享术语并更新 CONTEXT.md 与 ADR
- 按红绿重构循环实现功能或修复缺陷
- 分阶段诊断难复现的缺陷与性能退化
- 扫描代码库并生成架构改进候选报告

核心亮点：小技能组合成工程流程。每项技能聚焦一个工程环节，可由用户主动调用或由 Agent 按任务触发；它们把需求澄清、设计、测试、诊断和评审串成可调整的工作流。

适合谁：需要约束 Claude Code、Codex 等编程 Agent 工作方式，并希望保留流程控制权的开发者
使用前准备：先选择插件或可编辑文件方式安装，并在每个仓库运行一次 /setup-matt-pocock-skills。

使用提醒：插件方式安装的是托管只读合集；文件方式需自行拉取更新。两种方式同时安装会让每项技能重复出现。

许可证：MIT

02｜pdf-inspector
先判断 PDF 是文本型还是扫描件，再把可提取内容按阅读顺序转成结构化 Markdown

它能做什么：

- 分类文本型、扫描型、图像型和混合型 PDF
- 标出缺少文本并需要 OCR 的具体页面
- 提取带坐标、字体和阅读顺序的文本
- 把标题、列表、链接和代码转换为 Markdown
- 结合绘图矩形与文本对齐识别表格

核心亮点：先分类，再按页分流 OCR。检测器抽样查看页面内容流，返回文档类型、置信度和待 OCR 页面；文本型页面直接进入本地提取与版面分析，避免整份文档一律送去 OCR。

适合谁：需要在本地处理报告、论文、发票或法律文档，并为 OCR 流程做分流的开发者
使用前准备：按调用环境安装对应组件：Python 需 maturin，Node.js 与浏览器使用各自 npm 包，Rust 使用 cargo。

使用提醒：项目本身不执行 OCR，也不依赖机器学习模型或外部服务；扫描页和编码损坏内容需要调用方转交 OCR。

许可证：MIT

03｜superpowers
让编程 Agent 先澄清设计，再按计划、测试和双阶段审查推进软件开发任务

它能做什么：

- 追问目标并把讨论整理成设计文档
- 创建隔离工作区并检查测试基线
- 拆分带文件路径和验证步骤的实现计划
- 按红绿重构循环逐项完成开发任务
- 完成测试后提供合并或保留分支选项

核心亮点：从需求确认到分支收尾。技能会在编码前触发需求讨论和设计确认，随后生成计划，由子 Agent 分项实现并接受规格、质量两轮审查，最后验证测试并让用户决定如何处理分支。

适合谁：希望编程 Agent 遵循明确研发流程，而不是收到需求后立即写代码的个人或团队
使用前准备：需按所用编程 Agent 分别安装；同时使用多个 Agent 时，每个运行环境都要单独安装。

使用提醒：设计需要用户确认后才会生成实现计划，执行计划前也需用户明确开始；不同编程 Agent 的更新方式可能不同。

许可证：MIT
