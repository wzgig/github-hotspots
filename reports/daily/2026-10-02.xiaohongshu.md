01｜OpenShell
为自主 Agent 提供受策略控制的私有运行环境

它能做什么：

- 隔离每个 Agent 的文件、进程和网络访问
- 检查每次网络连接是否符合策略
- 把凭据限制在获批的 API 端点
- 在策略变更前标记新增访问风险
- 通过网关管理沙箱、策略和访问

核心亮点：给自主 Agent 加上可审查的权限边界。每个 Agent 在隔离沙箱中运行，内核拦截文件、系统调用和网络访问；策略变更先经形式化验证，再交给人工审核。

适合谁：需要让自主 Agent 访问文件、安装包和调用 API，同时控制数据、网络与凭据范围的团队
使用前准备：需要 Linux、Apple Silicon 的 macOS，或实验性的 Windows WSL 2，并准备 Docker、Podman 或主机虚拟化。

使用提醒：策略变更中的高风险新增访问会等待人工审核；Windows WSL 2 仍属实验支持。

许可证：Apache-2.0

GitHub 搜索：NVIDIA/OpenShell

02｜openrig
把多个编程 Agent 组织成可持续协作的团队

它能做什么：

- 用 YAML 定义 Agent 团队拓扑和角色关系
- 一条命令启动 tmux 会话与 Agent 团队
- 用终端界面查看座席、项目和运行状态
- 发现并接管已有的 Agent 会话
- 保存团队拓扑并在之后恢复

核心亮点：把终端会话组织成可恢复的 Agent 团队。OpenRig 由 CLI、终端界面、MCP 服务和本地守护进程组成，底层用 tmux 管理会话，让角色、上下文和团队状态保持在固定位置。

适合谁：需要让 Claude Code、Codex 等编程 Agent 持续分工、沟通并复用上下文的开发者与技术负责人
使用前准备：需要 Node.js 22 或 24、tmux，以及 macOS 或 Linux；原生 Windows 尚不支持，WSL2 未经过测试。

使用提醒：安装和启动会写入信任设置、可执行钩子及工作区文件；README 建议首次使用前备份相关文件。

许可证：Apache-2.0

为什么本期上榜：过去 24 小时净增 +701 Star（历史快照核验）
GitHub 搜索：mvschwarz/openrig

03｜hyperframes
把 HTML、CSS 和媒体组合成可预览的 MP4 视频

它能做什么：

- 初始化 HTML 视频项目
- 用时间属性编排画面和媒体轨道
- 在浏览器中实时预览 composition
- 检查项目并诊断关键帧动画
- 在本地、Docker 或 AWS Lambda 中渲染视频

核心亮点：用网页技术完成可重复的视频渲染。以 HTML 定义画面，用 data 属性标记时间和轨道；浏览器逐帧采集后交给 FFmpeg 编码，因此同一输入可得到相同视频。

适合谁：需要用 HTML 制作产品宣传、PR 讲解、数据动画或社交视频的开发者与内容团队
使用前准备：需要 Node.js 22+ 和 FFmpeg。

使用提醒：本地渲染依赖无头 Chrome 与 FFmpeg；完整仓库开发还需要 Git LFS。

许可证：Apache-2.0
