01｜ECC
给 AI 编程代理补上一套计划、测试、复盘与记忆工作流

它能做什么：

- 规划功能并生成实施蓝图
- 按 RED→GREEN→REFACTOR 推进测试
- 从新上下文复查代码与回归风险
- 跨会话保存并检索项目记忆
- 扫描提示词、Hooks、MCP 与密钥配置

核心亮点：把代理变成可复盘的工程流程。ECC 将技能、代理、规则、Hooks 和记忆组合起来，让 AI 按计划、测试、实现、审查、验证的顺序推进任务。

适合谁：使用 Claude Code、Codex 等代理完成开发、审查和安全检查的个人与团队
使用前准备：通用安装需要 Node.js 18 或更新版本；Claude 插件路径还需要 Git 和 Claude Code 2.1 或更新版本。

使用提醒：不同宿主的能力并不完全一致；Codex Hooks 需要明确授权，GitHub Copilot 不提供 Hooks、代理委派或原生技能发现。

许可证：MIT

02｜skills
把工程经验拆成可组合技能，帮助 AI 先对齐需求、再测试和交付

它能做什么：

- 通过提问明确需求和设计分歧
- 建立项目共享术语与决策文档
- 用 TDD 推进功能或缺陷修复
- 按阶段诊断问题并补回归测试
- 扫描架构并拆成可执行工单

核心亮点：把工程基本功做成可调用技能。这套技能把需求澄清、领域建模、TDD、调试、代码评审和架构设计拆成小模块，可按任务组合使用。

适合谁：希望让 AI 编程代理遵循工程实践、减少返工的开发者和团队
使用前准备：先选择 Claude Code 插件或 skills.sh 文件安装方式，再运行 /setup-matt-pocock-skills 配置 issue 追踪器和

使用提醒：插件是托管的只读集合，skills.sh 版本可编辑但需手动更新；两种安装方式不能同时使用。

许可证：MIT

03｜ponytail
让 AI 编程代理先复用、再少写，减少不必要的实现和过度设计

它能做什么：

- 审查当前 diff，列出可删除的过度设计
- 扫描整个仓库，寻找过度工程化位置
- 切换规则强度，控制代理的介入程度
- 把暂缓的 ponytail 快捷项收进债务清单
- 在支持的代理中注入持续规则与技能

核心亮点：用 YAGNI 阶梯约束代理。ponytail 让代理先判断是否需要新增代码，再依次尝试复用现有实现、标准库、原生能力和已安装依赖，最后才写最小可行方案。

适合谁：想控制 AI 生成代码规模、成本和复杂度的开发者与团队
使用前准备：Claude Code 和 Codex 插件的生命周期 Hooks 需要 Node.js 在 PATH 中；没有 Node.js 时，技能仍可使用。

使用提醒：命令需要支持技能的宿主；Cursor、Copilot 等指令适配器只加载规则，不提供命令切换或 Hooks。

许可证：MIT
