01｜TencentDB-Agent-Memory
把对话、文档和代码沉淀成可共享记忆，让多个 Agent 少重复学习、直接接着做

它能做什么：

- 提取对话中的 Chat Memory 与 Skill
- 把文档整理成带链接图的 Wiki
- 为代码建立符号与调用关系图
- 按团队、角色和 Agent 分配记忆资产
- 按需检索内容并控制上下文预算

核心亮点：把团队经验变成 Agent 可调用的记忆资产。把对话提炼为 Chat Memory 和 Skill，把文档、代码整理为 Wiki 与 CodeGraph，再由 Memory Hub 按权限分配给 Agent。

适合谁：需要让多个 Agent 共享项目经验、文档和代码上下文的团队或开发者
使用前准备：需配置两组 LLM 参数，并启动 memory-core、memory-hub、proxy 三项服务。

使用提醒：Wiki 和 CodeGraph 异步处理；当前优先支持公共 HTTPS 仓库，私有仓库和 SSH 支持仍在完善；记忆绑定仍需人工操作。

许可证：MIT

02｜agent-skills
把资深工程师的研发流程整理成 Agent 可执行的技能包，覆盖从需求到发布的关键环节

它能做什么：

- 澄清需求并产出项目规格
- 拆分计划并安排可验证任务
- 按增量方式实现并测试代码
- 执行代码审查、安全与性能检查
- 准备发布、迁移和可观测性工作

核心亮点：把研发规范变成可执行工作流。技能包覆盖需求定义、计划拆解、增量实现、测试验证、代码审查和发布，并通过命令或自动触发接入多个 Agent。

适合谁：希望让编程 Agent 按统一研发规范完成需求、编码、测试和发布的开发者
使用前准备：需使用支持技能或指令文件的 Agent；可通过 npx skills 安装技能包。

使用提醒：单独安装某个技能时不会复制仓库级 references 目录；需要整仓集成、克隆仓库或补齐对应检查清单。

许可证：MIT

03｜superpowers
让编程 Agent 先澄清需求、再规划实现，并通过测试和审查把任务推进到可交付

它能做什么：

- 通过提问把想法收敛成设计
- 创建隔离 worktree 并检查测试基线
- 把方案拆成带验证步骤的小任务
- 执行 RED-GREEN-REFACTOR 测试循环
- 派发子 Agent 并进行两阶段审查

核心亮点：让 Agent 按方法完成软件开发。它用 brainstorming、writing-plans、TDD 和 subagent-driven-development 等技能串起流程，并在任务间加入验证与审查节点。

适合谁：希望让编程 Agent 按固定方法推进复杂软件开发任务的个人开发者和团队
使用前准备：需按所用 coding agent 分别安装 Superpowers 插件；不同 harness 的安装方式不同。

使用提醒：可选视觉 companion 默认会加载带版本号的官网图标，不包含项目详情；可用 `SUPERPOWERS_DISABLE_TELEMETRY` 关闭。
