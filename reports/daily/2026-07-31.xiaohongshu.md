01｜speech-to-speech
把语音检测、转写、大模型回复和语音合成串成可替换的实时语音智能体管线

它能做什么：

- 检测说话边界并处理轮次切换
- 实时转写语音并返回部分文本
- 流式生成回复、工具调用和合成音频
- 替换语音识别、大模型和语音合成后端
- 通过本地、Realtime、WebSocket 或 TCP 模式运行

核心亮点：四段可替换的语音管线。语音先经过活动检测和转写，再交给大模型生成文本与工具调用，最后合成为音频流；每一段都能按设备、语言和部署方式更换后端。

适合谁：适合开发语音助手、机器人对话后端或自定义实时语音客户端的团队
使用前准备：需要 Python 3.10+；不同后端还需匹配 CUDA、Apple Silicon 或额外依赖

使用提醒：TCP 模式不含打断处理、实时转写事件和工具调用事件；LLM 代理自身不做认证或限流

许可证：Apache-2.0

为什么本期上榜：过去 24 小时净增 +906 Star（历史快照核验）
GitHub 搜索：huggingface/speech-to-speech

02｜openwork
把技能、插件、MCP 与办公服务集中起来，让多个智能体和团队复用同一套 AI 工作流

它能做什么：

- 搜索当前用户可调用的能力
- 执行已分配的技能、插件和服务
- 跨兼容智能体复用同一套工作流
- 发布技能与插件并分配给成员或团队
- 管理模型访问、桌面策略和应用版本

核心亮点：一个 MCP 连接多套智能体。客户端只需接入 OpenWork MCP，就能搜索和执行组织分配的能力；团队可在管理端发布技能、配置连接，并按组织、团队或个人控制访问。

适合谁：适合需要跨智能体共享工作流，或统一管理团队模型、插件与办公服务连接的组织
使用前准备：需要兼容 MCP 的智能体客户端；接入后需通过浏览器登录并选择组织

使用提醒：桌面应用不是必需；从现有智能体使用时，客户端需要兼容 MCP

为什么本期上榜：过去 24 小时净增 +823 Star（历史快照核验）
GitHub 搜索：different-ai/openwork

03｜ECC
把计划、测试、实现、复审、验证与记忆固化进编码智能体，减少每次靠提示词重建流程

它能做什么：

- 规划功能并生成可确认的实施方案
- 用测试先行流程保留验证证据
- 在新上下文中审查代码与回归风险
- 扫描智能体配置、权限与提示注入风险
- 跨多种智能体环境同步技能和记忆

核心亮点：让编码智能体按工程闭环工作。ECC 把规划、测试先行、实现、独立审查、最终验证和经验沉淀连成固定流程，再用技能、代理、规则与 hooks 分别承载按需能力、隔离任务和自动检查。

适合谁：适合希望统一编码智能体工作方式，并加强测试、审查、安全扫描和会话交接的研发团队
使用前准备：需先准备 Claude Code、Codex 或其他受支持的智能体环境，并选择对应安装方式

使用提醒：同一智能体不能叠加安装方式；Codex 尚无 Claude 式 hooks 执行能力；记忆内容仍需人工核验

许可证：MIT
