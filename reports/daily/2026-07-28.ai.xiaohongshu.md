AI 项目的名字往往很抽象。这一期不堆术语，只讲清它替谁做什么、能完成哪些任务，以及是否值得加入你的工具箱。

先看结论：
- impeccable：给 AI 编码工具补上一套前端设计工作流，从建立设计上下文到审查、打磨和浏览器迭代

01｜impeccable
给 AI 编码工具补上一套前端设计工作流，从建立设计上下文到审查、打磨和浏览器迭代

它能做什么：

- 初始化产品定位、品牌语气和设计规范
- 规划界面结构后再进入代码实现
- 审查层级、清晰度与视觉表达
- 检查无障碍、响应式和性能问题
- 在浏览器中对界面元素迭代多个方案

核心亮点：贯穿项目的设计上下文。初始化会生成 PRODUCT.md，并可生成 DESIGN.md；后续命令持续读取受众、品牌方向、颜色、字体和组件信息，减少每轮设计任务重新解释背景。

适合谁：使用 AI 编码工具制作落地页、应用界面或仪表盘，需要统一设计方向并检查成品的团队
使用前准备：在项目根目录运行 npx impeccable install，再执行 /impeccable init。

使用提醒：安装或更新后需重载编码工具；Codex 用户还要在 /hooks 中人工批准项目 Hook。

许可证：Apache-2.0

02｜open-code-review
把确定性审查流程与 LLM Agent 结合，读取代码变更并生成精确到行的结构化审查意见

它能做什么：

- 审查暂存、未暂存和未跟踪的变更
- 比较分支范围或检查单个提交
- 扫描完整文件或指定目录
- 定位问题行并输出结构化评论
- 恢复中断的分支或提交审查会话

核心亮点：确定性流程与 Agent 分工。工程逻辑负责选文件、组合相关文件、匹配规则和校准评论位置；Agent 负责按场景调用工具、读取上下文并判断问题，兼顾流程约束与动态分析。

适合谁：需要审查工作区、分支、提交或完整目录，并希望把检查接入日常开发与 CI/CD 的研发团队
使用前准备：需要 Git >= 2.41；常规模式还要配置 LLM 提供方、模型和 API key。

使用提醒：其设计取舍偏向提高精确率、减少误报，因此召回率低于 README 对比的通用 Agent；委托模式可免配 OCR 的 LLM。

许可证：Apache-2.0

为什么本期上榜：过去 24 小时净增 +996 Star（历史快照核验）
GitHub 搜索：alibaba/open-code-review

03｜firecrawl
把网页搜索、抓取和交互统一成 API，输出适合程序与 AI 继续处理的 Markdown 或结构化数据

它能做什么：

- 搜索网页并返回结果页面的完整内容
- 把单个网址转换为 Markdown 或 JSON
- 发现并抓取网站内的全部页面
- 批量异步处理多个网址
- 点击、滚动、输入或等待后再提取页面

核心亮点：抓取前先完成网页交互。同一流程可先抓取页面，再通过提示词或代码执行点击、滚动、输入、等待等动作，最后读取操作后的内容，适合普通静态抓取无法覆盖的页面。

适合谁：为 AI Agent、搜索、研究或数据管道接入实时网页内容，需要统一抓取接口的开发者
使用前准备：使用托管服务需注册并获取 API key；本地运行或自托管需按对应指南部署。

使用提醒：云端版本包含额外功能；抓取时需由使用者遵守网站政策、隐私政策和使用条款，默认遵循 robots.txt。

许可证：AGPL-3.0（The SDKs and some UI components are licensed under the MIT License.）
